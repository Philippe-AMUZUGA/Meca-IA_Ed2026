# Méca-IA

**Avertissement :** les jeux de données de ce dépôt ont un sens mécanique donné par transformation : les noms de colonnes, et parfois les valeurs, sont modifiés pour obtenir des ordres de grandeur réalistes. Certains partent de jeux publics connus, d'autres sont générés par l'auteur. Les métamodèles et les lois issus des estimateurs d'apprentissage automatique de ces notebooks ne doivent pas servir en application réelle. Pour refaire l'apprentissage, chargez vos propres données : c'est la méthode qui compte.

Exercices, corrigés et jeux de données qui accompagnent l'ouvrage *Méca-IA* (édition 2026, version 0.1.0 du dépôt). Le dépôt réunit les 44 défis et les 41 jeux de données que le livre mentionne.

Apprendre le machine learning sur des problèmes d'ingénieur : mécanique, industrie, productique. Chaque défi part d'un cas concret, d'un jeu de données et d'un score à battre.

## À qui il sert

- Aux lecteurs du livre Méca-IA : les jeux et les défis de chaque chapitre sont ici.
- À toute personne qui veut s'entraîner sur des données d'ingénierie, sans lire le livre.

Aucun prérequis si vous venez d'une filière scientifique. Ce dépôt est autonome : tout ce que le livre mentionne pour l'étudier s'y trouve, jeux compris. Pour apprendre le langage Python avant ou pendant la lecture, le livre Méca-Py (Python pour l'ingénierie mécanique, industrielle et productique) en est le complément ; il a son propre dépôt : <https://github.com/philippe-amuzuga/Meca-PY_Ed2026>.

## Ce que vous y trouvez

- Des jeux de données au format Excel, dans `donnees/`, présentés dans [`donnees/LISEZMOI.md`](donnees/LISEZMOI.md).
- Pour chaque défi, un notebook sujet et un notebook corrigé, dans `meca-ia/`, rangés par chapitre du livre.
- `generateurs/` : les scripts qui fabriquent les jeux simulés `Qualite_soudure` et `Diagnostic_Vibratoire` (graine 42), qui régénèrent le jeu et contrôlent ses propriétés.
- Le score de référence à battre, mesuré sur une base de test désignée.
- Un bouton « Ouvrir dans Colab » devant chaque notebook.
- `manifest.json` : la liste complète des jeux et des défis, d'où sont tirés les tableaux ci-dessous.

## Démarrer en trois étapes

1. Cloner le dépôt.
2. Installer les bibliothèques.
3. Ouvrir un notebook.

```
git clone https://github.com/philippe-amuzuga/Meca-IA_Ed2026.git
cd Meca-IA_Ed2026
pip install -r requirements.txt
jupyter lab
```

Les notebooks sont exécutés sous Python 3.12 avec les versions de [`requirements.txt`](requirements.txt). Chaque notebook lit son jeu dans le dossier `donnees/`, par un chemin relatif résolu dans sa première cellule de code.

## Dans Colab

Cliquer sur le bouton « Ouvrir dans Colab » du tableau des défis. Colab ouvre le notebook depuis GitHub, à la référence `main` du dépôt. Les bibliothèques usuelles y sont déjà installées.

Un notebook ouvert seul ne trouve pas les jeux du dépôt. Deux cellules du début de chaque notebook y pourvoient :

- la première cellule de code récupère le jeu du défi dans le dépôt public ; c'est la seule cellule qui accède au réseau ;
- la cellule « Préparation du dépôt (Colab) » ne télécharge rien : elle cherche le dossier `donnees/` et, sur Colab, liste le jeu à téléverser. Pour le faire, ouvrir le panneau des fichiers de Colab, créer le dossier `donnees` à la racine de l'espace de travail et y téléverser le classeur listé, pris dans ce dépôt.

## La règle d'or

Ne jamais entraîner un modèle sur la base de test.

- Ne pas l'ajuster, ne pas choisir ses réglages en regardant le score de test.
- La base de test sert une seule fois, à la fin, pour mesurer.
- Sinon le score devient optimiste : il ne mesure plus la généralisation.

Chaque défi désigne sa base de test : un découpage fixé (méthode, proportion, graine 42) dont l'empreinte figure dans `manifest.json`. Les deux défis sans étiquette, E10-1 et E10-3, s'évaluent sur toutes les lignes, la colonne de référence restant cachée pendant l'analyse. Le jeu de données n'est jamais modifié pour un défi.

## Pourquoi coder soi-même

Des logiciels existent déjà. Coder soi-même ses modèles donne pourtant trois choses :

- la maîtrise de bout en bout, de la donnée brute au résultat ;
- la personnalisation à son propre problème ;
- la compréhension de ce que le modèle fait, et de ses limites.
